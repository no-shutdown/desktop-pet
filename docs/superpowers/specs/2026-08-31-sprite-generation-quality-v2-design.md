# Sprite Generation Quality V2 Design

日期：2026-08-31

## 背景

当前 AI 生成流程把参考图分析结果作为文字提示词发送给基础图生成模型，再把基础图平铺为参考图生成各个动作行。现有流程存在四类可见问题：真人照片容易被模型直接渲染成写实或 3D 角色；头发、身体和道具之间的封闭小背景区域可能残留；不同动作或帧之间可能发生镜像、转身或视角漂移；`working` 动作有时只生成独立键盘而不是完整笔记本电脑。现有行切割还会对每帧单独重新居中，导致桌面等共享场景元素产生横向漂移。

此前已确认的待机要求也继续保留：`idle` 是站立不动的静态待机，不要求全身呼吸、缩放、摇摆或眨眼。

## 目标

- 真人照片明确转换成可爱的 2D Q 版/扁平插画角色。
- 卡通、动漫、像素画和其他已有插画保留原有画风，不强制统一成另一种风格。
- 清除边缘背景、斜向连接背景以及头发间等小型封闭背景缝隙，同时避免大面积误删角色内部颜色。
- 所有动作和每一帧使用与基础图一致的镜头、身体朝向和头部朝向。
- `working` 始终要求一台放在桌面上的完整打开笔记本电脑，包含屏幕面板、转轴和键盘底座。
- 保持桌面、椅子、笔记本等共享场景元素在帧间的固定坐标。

## 非目标

- 不引入外部目标检测、分割模型或新的在线服务。
- 不尝试用后处理自动把侧脸变成正脸；朝向由基础图、参考图和动作提示词共同锁定。
- 不重构现有生成 provider、Tauri 运行目录或前端创建器流程之外的功能。

## 设计

### 1. 明确参考图风格

在创建器的分析步骤增加“参考图类型”选择，并把选择结果贯穿整个生成 run：

- `realistic`：真人照片或写实人物。基础图提示词加入 2D Q 版转换契约：圆润简化的形体、大头小身、可爱的表情、清晰线稿、平涂或轻微 cel shading、明亮协调的配色；同时明确禁止 photorealistic、3D render、CGI、塑料质感、真实皮肤纹理、电影级光照和写实材质。
- `stylized`：卡通、动漫、像素画或已有插画。提示词要求保留原参考风格的线条、比例、配色、材质和渲染方式，禁止强制改成 3D 或另一种通用 Q 版风格。

选择结果以 `SourceStyle` 类型保存在前端 `WizardData`，通过 `generate_base_preview` 传入 Rust，并保存到 `GenerationRunManifest`。旧 manifest 缺少该字段时使用 `stylized` 默认值，保证旧 run 可以读取且不会被新规则意外转成 2D Q 版。基础图和动作行都显式接收该风格契约；视觉分析提示词同时要求识别并描述原图的媒介/画风，避免分析服务把已有插画误写成统一的 Q 版描述。

### 2. 基础图与动作图提示词

基础图始终是一个正面、完整、居中的 canonical pose。风格契约紧随角色描述插入，动作图再次重复，避免动作生成模型只继承动作而丢失风格。

所有状态共用同一个方向契约：使用 canonical base 的精确镜头、身体朝向、头部朝向和左右关系；每一帧禁止镜像、翻转、侧转、三分之四视角变化或局部反向。`sleeping` 不再允许“three-quarter or front”，而是与其他状态一样锁定基础图方向。

`working` 使用正向和反向双重约束：角色坐在桌后，桌面位于画面下三分之一和肘部高度；桌面上只有一台完整的打开笔记本，屏幕面板通过转轴连接到水平键盘底座，屏幕和键盘都清晰可见，设备平放在桌面上，双手敲击键盘。禁止 standalone keyboard、keyboard-only、tablet、closed laptop、lap-held laptop、手持设备、独立显示器以及帧间更换或漂移。

`idle` 使用静态帧契约：八列是同一站立姿势的稳定副本，不要求制造差异，不呼吸、不缩放、不摇摆、不移动四肢、不眨眼。

### 3. 抠图与背景清理

保留当前从边框采样实际背景色的能力，但将 matte 处理拆成两个受限阶段：

1. 对配置的色键颜色和从输出边缘采样到的背景颜色分别计算颜色距离。对边缘连接的背景使用 8 邻域 flood fill，以覆盖头发缝隙中的斜向单像素连接；只有颜色接近背景且从边缘可达的像素才会被移除。
2. 对未连接边缘的小型背景色连通分量做封闭孔清理。分量必须与背景颜色接近、没有接触画布边缘且不超过固定上限；达到上限的分量保留，避免把大块角色区域误判为孔洞。该阶段复用同一套硬阈值和抗锯齿 alpha ramp，并把 alpha 为零的像素 RGB 归一为零。

配置色键的近似颜色允许被清除，即使它处于封闭区域，因为提示词明确禁止色键进入角色；采样背景色仍必须经过连通性限制，保护角色内部可能相近的黑色、白色或其他颜色。抠图在缩放前执行，避免背景色先被 Lanczos 插值到角色边缘。

### 4. 共享场景坐标的行切割

`normalize_horizontal_row` 在移除背景后先计算整行可见内容的全局边界，把内容宽度按八列用向上取整分成固定 source slots。每一列都裁剪完整的固定 slot，短 slot 用透明像素补齐；所有列使用同一缩放比例、同一水平 slot 偏移和同一底部基线。

不再根据每一帧自己的可见宽度重新居中。这样角色动作可以在自己的 slot 内变化，但桌面、椅子、笔记本等跨帧共享的场景坐标不会因为每帧宽度不同而横向漂移。

### 5. 数据流与兼容性

数据流为：

```text
AnalyzeStep sourceStyle
  -> WizardData.sourceStyle
  -> generate_base_preview(sourceStyle)
  -> GenerationRunManifest.sourceStyle
  -> build_base_prompt/build_row_prompt(sourceStyle)
```

`sourceStyle` 使用可序列化的 `realistic`/`stylized` 枚举。命令参数采用可选字符串并在后端集中校验，旧调用缺省为 `stylized`；未知值返回明确错误。manifest 新字段使用 serde 默认值，旧生成 run 仍可加载。

## 测试策略

- TypeScript：验证分析步骤渲染风格选择，下一步把选择值传给创建器；视觉分析提示词包含“识别并保留原画风”的要求。
- Rust prompt：验证真人风格包含完整 2D Q 版约束和 3D/写实排除词，卡通风格包含保留原画风约束；验证所有状态相同的朝向锁定、`sleeping` 不含三分之四视角、`working` 同时要求屏幕和键盘且排除独立键盘；验证 idle 静态契约。
- Rust sprite：验证色键近似色的封闭小孔、8 邻域斜向孔洞、透明 RGB 清零、大型封闭分量保留；验证固定 source slot 使桌面像素在所有帧保持同一相对坐标。
- 回归：运行 Rust library tests、Vitest、TypeScript/Vite build 和 `git diff --check`。

## 验收标准

- 选择真人照片后，生成提示词明确要求可爱 2D Q 版，并明确禁止 3D/写实结果。
- 选择卡通/插画后，提示词明确要求保留原画风。
- 头发间的小型背景缝隙和斜向连接背景不再出现在透明结果中，角色主体细节仍保留。
- 四个动作及八个帧都使用相同朝向，不出现镜像或视角跳变。
- `working` 的每一帧都要求完整打开笔记本，而不是单独键盘。
- 桌面等共享元素在帧间不因切割算法重新居中而漂移。
- 旧 manifest 可读取，新流程测试全部通过。
